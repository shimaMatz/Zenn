## はじめに

この調査を行ったきっかけは、以前、前の会社の上司と会った際にGoのパフォーマンスの良さについて話を聞いたことでした。最近、Kubernetes（k8s）を使ったプロジェクトに参画し、大量のリクエストを処理する環境に身を置くようになったことで、パフォーマンスについて考える機会が増えました。そこで、実際に各言語のパフォーマンスを定量的に測定してみようと考え、本調査を実施しました。

本記事では、**Go、Node.js、Python、Ruby、PHP**の私が過去に使用していたことのあるプログラミング言語で同一仕様のAPIを実装し、Docker環境で公平な条件下でパフォーマンスを測定しました。実測したRPS（Requests Per Second）やレイテンシから、各言語の特性と適切なユースケースを明らかにします。

## プロジェクト概要

### 目的

- 各言語の処理性能を定量的に測定・比較
- 2CPU、4GBメモリという現実的な環境でのRPSを体感
- SaaS構築時の言語選定の判断材料を提供

### 対象言語とフレームワーク

| 言語 | フレームワーク | バージョン | ポート |
|------|---------------|-----------|--------|
| **Go** | Gin | 1.21+ | 8081 |
| **Node.js** | Express | 18+ | 8082 |
| **Python** | FastAPI + Uvicorn | 3.11+ | 8083 |
| **Ruby** | Sinatra + Puma | 3.2+ | 8084 |
| **PHP** | Slim + Nginx/FPM | 8.2+ | 8085 |

### 実装したAPIエンドポイント

すべての言語で以下の4つのエンドポイントを同一仕様で実装しました：

```
GET /hello
- シンプルなJSON返却（計算処理なし）
- フレームワークのオーバーヘッド測定用

GET /users/:id
- 配列からユーザー検索（O(1)アクセス）
- 軽量なロジック処理の性能測定用

GET /users
- ユーザー一覧取得（10件）
- 配列操作とJSON変換の性能測定用

GET /compute
- CPU負荷のかかる計算処理（平方根計算 100万回）
- CPU集約的処理での言語差を測定用
```

## ベンチマーク結果

### シナリオ1: 軽負荷（10接続）- `/hello`

**実際の負荷感**: 個人ブログや社内ツールの通常時。サーバーはほぼ待機状態。

| 言語 | RPS | 平均レイテンシ | P99レイテンシ |
|------|-----|--------------|--------------|
| **🥇 Go** | **14,568** | 3.09ms | 59.14ms |
| 🥈 Node.js | 8,901 | 2.08ms | 36.28ms |
| 🥉 Python | 5,896 | 7.35ms | 83.64ms |
| Ruby | 3,506 | 8.45ms | 77.57ms |
| PHP | 2,834 | 9.18ms | 60.81ms |

**ポイント**:
- Goは1秒間に**14,568リクエスト**を処理（= 1日で約12.6億リクエスト）
- Node.jsは最も低いレイテンシ（2.08ms）でレスポンス
- GoとPHPで**5倍以上**の性能差

### シナリオ2: 中負荷（100接続）- `/users/1`

**実際の負荷感**: 中規模Webサービスの通常運用時。月間100万PV程度のサイト。

| 言語 | RPS | 平均レイテンシ | P99レイテンシ |
|------|-----|--------------|--------------|
| **🥇 Go** | **26,198** | 14.61ms | 157.99ms |
| 🥈 Node.js | 10,415 | 22.92ms | 532.70ms |
| 🥉 Python | 6,837 | 22.64ms | 139.55ms |
| PHP | 3,310 | 36.79ms | 171.82ms |
| Ruby | 2,787 | 63.70ms | 425.71ms |

**ポイント**:
- Goは1秒間に**26,198リクエスト**（= 1日で約22.6億リクエスト）
- GoはNode.jsの**2.5倍**のスループット
- 100接続でもGoの平均レイテンシは14.61ms（体感的に瞬時）

### シナリオ3: 高負荷（500接続）- `/users`

**実際の負荷感**: 大規模サービスのピーク時。バーゲンセールやニュース速報時のアクセス集中。

| 言語 | RPS | 平均レイテンシ | P99レイテンシ |
|------|-----|--------------|--------------|
| **🥇 Go** | **26,452** | 38.24ms | 336.77ms |
| 🥈 Node.js | 13,239 | 38.79ms | 111.86ms |
| 🥉 Python | 7,000 | 75.40ms | 231.94ms |
| Ruby | 4,138 | 43.37ms | 638.70ms |
| PHP | 3,361 | 161.14ms | 727.03ms |

**ポイント**:
- Goは500接続でもRPSがほぼ変わらず（優れたスケーラビリティ）
- Node.jsはP99が111msと優秀（99%のユーザーが快適）
- PHPは161msの平均レイテンシ（体感的にもたつく）

### シナリオ4: CPU集約処理（100接続）- `/compute`

**実際の負荷感**: 画像処理、暗号化、データ分析など計算が必要な処理。

| 言語 | RPS | 平均レイテンシ | P99レイテンシ |
|------|-----|--------------|--------------|
| **🥇 Go** | **1,255** | 131.44ms | 737.37ms |
| 🥈 Node.js | 245 | 403.91ms | 473.76ms |
| 🥉 PHP | 104 | 940.82ms | 1.48s |
| Python | 35 | 1.27s | 1.99s |
| Ruby | 30 | 1.03s | 1.94s |

**ポイント**:
- GoはNode.jsの**5倍**、PythonとRubyの**40倍**の性能
- Python/Rubyは1リクエストに1秒以上かかる
- CPU処理では言語の根本的な速度差が顕著に現れる

- 個人ブログ（1日1,000PV）
- 開発環境のテスト

**体感**: ほぼ瞬時にレスポンス。サーバーリソースは余裕。

### 100接続（中負荷）

**現実の例**:
- 中規模ECサイト（月間100万PV）
- SaaSアプリ（同時ユーザー100人）
- 地方ニュースサイトの平常時

**体感**:
- Goは快適（14ms）
- Node.jsも快適（22ms）
- PHPはやや遅い（36ms）

### 500接続（高負荷）

**現実の例**:
- 全国ニュース速報時
- ECサイトのタイムセール開始直後
- SNSでバズった時のアクセス集中

**体感**:
- Goは安定（38ms）
- Node.jsも許容範囲（38ms）
- PHPは遅い（161ms）← ユーザーが「重い」と感じる

### CPU集約処理

**現実の例**:
- 画像のリサイズ・圧縮
- PDFの生成
- 複雑な計算処理
- 暗号化処理

**体感**:
- Go: 131ms（実用的）

- Python/Ruby: 1秒以上（ユーザーは離脱する）

## 言語選定ガイド

### Goを選ぶべき場合 ✅

- 高トラフィックが予想される（RPS 10,000+）
- レイテンシが重要（金融、ゲーム）
- CPU集約的な処理が多い
- スケーラビリティが必要
- マイクロサービスアーキテクチャ

### Node.jsを選ぶべき場合 ✅

- I/O処理が中心（API Gateway、プロキシ）
- リアルタイム通信（WebSocket、SSE）
- JavaScriptエコシステムを活用したい
- フロントエンド開発者が多い
- 中程度のトラフィック

### Pythonを選ぶべき場合 ✅

- ML/AIライブラリとの統合が必要
- 開発速度を最優先
- データ分析・科学計算
- プロトタイピング
- 中程度のトラフィック

### Rubyを選ぶべき場合 ⚠️

- MVPの迅速な開発
- スタートアップの初期フェーズ
- 管理画面・内部ツール
- 開発者の幸福度を重視
- トラフィックは少なめ

### PHPを選ぶべき場合 ⚠️

- WordPress/Laravel等の既存エコシステム活用
- レガシーシステムの移行
- 従来型Webアプリケーション
- 共有ホスティング環境
- トラフィックは少なめ

## 重要な発見

### 1. Goの圧倒的優位性

- 全シナリオで他言語を大きく上回る
- 軽負荷: Node.jsの1.6倍
- 中負荷: Node.jsの2.5倍
- CPU処理: Node.jsの5倍、Python/Rubyの40倍

### 2. CPU処理での言語差

- 計算処理では言語の根本的な速度差が顕著
- Goの圧倒的な優位性（コンパイル言語の強み）
- Python/RubyはCPU処理に不向き

### 3. スケーラビリティ

- **Go**: 10接続→500接続でRPSが1.8倍に向上
- **Node.js**: 安定したスケーリング
- **Ruby/PHP**: 高負荷でレイテンシが大幅に増加

### 4. 実用的な判断基準

- **50ms以下**: 快適
- **50-100ms**: 許容範囲
- **100-200ms**: やや遅い
- **200ms以上**: ユーザーが不快に感じる

| `/users` | 7,000+ | **26,452** | ✅ 予測を大幅に上回る |

Goの実測値は予測を大幅に上回り、特に中〜高負荷で驚異的な性能を発揮しました。

## まとめ

5つの主要プログラミング言語で同一仕様のAPIを実装し、パフォーマンスを測定した結果、以下のことが明らかになりました：

1. **Goは全シナリオで圧倒的な性能**を発揮し、高トラフィックなSaaS構築に最適
2. **Node.jsはI/O処理で優秀**で、リアルタイム通信やAPI Gatewayに向いている
3. **PythonはML/AI統合や開発速度重視**のプロジェクトに適している
4. **Ruby/PHPは低〜中トラフィック**のアプリケーションや管理画面向け

言語選定は、パフォーマンスだけでなく、チームのスキルセット、エコシステム、開発速度なども考慮する必要があります。本記事が、あなたのプロジェクトに最適な言語を選ぶ判断材料になれば幸いです。
